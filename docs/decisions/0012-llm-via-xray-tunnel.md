# 0012 — Доступ к cliproxyapi через Xray (`cpa.golem`)

Статус: принято (выбор владельца 2026-10-27); в ролях включается флагом `xray_cpa_route_enabled`, по умолчанию выключено.

## Контекст
Клиенты LLM-агентов не гарантируют работу с секретным context path Caddy (`/<llm_path>/v1`): ccs префикс не поддерживает совсем, `pi-cliproxyapi-provider` ходит и на пути вне белого списка. Альтернатива — внешний порт хостера на cliproxyapi: номер выдают только после заказа VPS, 8317 напрямую (без TLS, rate limit, белого списка) открывать нельзя. Исследование и результаты прогонов: `docs/research/llm-access/`.

## Решение
Агент ходит на виртуальное имя `cpa.golem` (в DNS его нет) по HTTP через прокси mihomo; правило `DOMAIN,cpa.golem,<узел VPS>`. На VPS Xray направляет это имя в outbound `freedom` с `redirect 127.0.0.1:8317` (правило выше `geoip:private`). Наружу нужен только 443 (VLESS+WS+TLS), шифрование — TLS Caddy. Аутентификация LLM — Bearer `access.api-keys`. Агенты видят не `cpa.golem`, а локальный адрес `http://127.0.0.1:<GOLEM_CPA_LLM_PORT>` (по умолчанию 18317, не 8317): клиент VLESS пробрасывает порт на `cpa.golem:8317` через узел VPS (mihomo: секция `tunnels:`, проверено; v2rayN — Не проверено). Прокси-режим с именем `cpa.golem` тоже работает. Прямой путь по `llm_path` через Caddy остаётся для клиентов без прокси (omp).

## Последствия
- Порт хостера и второй TLS-listener Caddy не нужны; SSH-туннель для LLM не нужен.
- Проверено на Lima: pi (`pi-proxy-router` или `HTTP_PROXY`), omp (`PI_PROXY_*`, `HTTP(S)_PROXY`), ccs (API-профиль) получили ответ через mihomo→Xray→cpa; SSE через Caddy не буферизуется.
- Без запущенного mihomo имя не резолвится: LLM недоступен (fail-closed). ccs и omp при этом зависают/повторяют попытки.
- Белый список Caddy на этом пути не действует: cliproxyapi видит запрос с 127.0.0.1 как локальный, `/management.html` отвечает без ключа, `/v0/management/*` — по `management_key`. Доступ имеет любой владелец VLESS-uuid; владелец приравнивает uuid к ключу и принимает риск.
- Известная дыра: `localhost:8317` через VLESS не блокируется `geoip:private` (имя не резолвится на этапе routing, `freedom` резолвит само). Затрагивает и базовую конфигурацию. Риск принят, правило `domain:localhost → block` не добавлено.
- Клиенты: `docs/clients/ai-agents.md`; артефакт `cpa-access.txt`.

## Пересмотреть
Если uuid начнут выдавать не-владельцам (тогда ограничить правило по `user` и закрыть localhost), если появится внешний порт хостера и потребуется доступ без прокси, или при переходе на NetBird (отдельный ADR).
