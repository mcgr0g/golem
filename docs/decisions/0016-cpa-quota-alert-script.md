# 0016 - Алерты квот CPA: скрипт-таймер на Python

Статус: принято (выбор владельца 2026-11-09)

## Контекст
CPA не отдаёт «остаток квоты» напрямую. Пассивные сигналы лимита (`quota.signals`, заголовки апстрима последнего ответа) лежат в `GET /v8/management/credentials` и только для аккаунтов, через которые шёл трафик. Нужен алерт в Telegram при остатке 15/10/5%.

## Решение
Отдельная роль `cpa_quota_alert`: systemd-таймер раз в 15 минут запускает Python-скрипт (stdlib, Python 3.11 из Debian 12). Настройки - TOML из j2 (без секретов), секреты - `EnvironmentFile` 0600, состояние - `state.json` в `StateDirectory`. Пороговая логика - чистые функции с постоянными тестами. Telegram - через `telegram.env` роли `ops_timers`.

Отвергнуто:
- **Gatus поверх Management API:** условия по телу ответа не умеют искать запись по полю в массиве и сравнивать пороги по аккаунтам; нужен отдельный эндпоинт на каждый аккаунт и окно; ключ management оказался бы в конфиге Gatus.
- **bash + curl:** разбор JSON без `jq` (на сервере нет) и логика порогов хрупки.
- **Keeper, CPAMP, Oh-My-CPA, Grafana/VM:** алертов в Telegram нет или лишняя RAM и порт.

## Последствия
- Один дополнительный читатель Management API; ключ management открытым видом лежит в `/etc/golem/cpa-monitor.env` (0600, root). Конфиг CPA принадлежит панели (ADR 0014), хэш в нём может разойтись с SOPS при смене ключа в панели: скрипт останавливается после первой неверной попытки, процедура - `components/cliproxyapi.md`.
- «Запущен» шлётся после каждой загрузки сервера (решение владельца): по нему видно, что таймер жив.
- Разбор окон реализован только для Claude; Codex добавляется по реальному ответу.

## Когда пересмотреть
Если CPA начнёт отдавать остаток квоты прямо, или Gatus научится условиям по полю массива.
