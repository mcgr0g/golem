# 0010 — Секреты: sops + age; SSH-ключи

Статус: принято.

## Контекст
Секреты (UUID VLESS, секретные пути, ключи CPA, токены) нужны Ansible. Проект может стать открытым и форкаться; часть пользователей не работала с age/sops. Агент не должен видеть расшифрованные значения.

## Решение
- **sops + age** (коллекция `community.sops`, vars-плагин): шифруются значения, структура YAML читаема. Ansible-vault не используем.
- Секреты хоста — `infra/ansible/secrets/<host>.sops.yml`; каталог в `.gitignore` по умолчанию: шифртекст в публичной истории остаётся навсегда, и утечка age-ключа позже раскрыла бы секретные пути (стелс). В приватном репозитории убрать строку из `.gitignore` и коммитить — это штатный сценарий sops.
- Для новичков вся работа обёрнута в mise-задачи : `secrets:init` (создаёт age-ключ `~/.config/sops/age/keys.txt` при отсутствии, генерирует `.sops.yaml`, секреты хоста и шифрует), `secrets:edit <host>`, `secrets:rotate`. Инструкция — `operations/secrets.md`.
- Приватный age-ключ не покидает Mac владельца, в репозиторий и чат не попадает; бэкап — менеджер паролей. Агенту расшифрованные значения не показывать: Ansible расшифровывает при запуске, `no_log` на задачах с секретами.
- **SSH:** на VPS кладутся публичные ключи владельца: основной из Secretive (Secure Enclave, Touch ID на каждое подключение — подтверждение человека для прод-прогонов; тип ecdsa-sha2-nistp256, Debian 12 поддерживает) и резервный ed25519 с парольной фразой. Агенту без подтверждения доступен только Lima.

## Последствия
- Входные данные от владельца: публичные SSH-ключи, поддомен и токен DuckDNS, IP VPS и первичный доступ провайдера (только bootstrap), опционально Telegram-токен.
- Потеря age-ключа = потеря секретов хоста; для VPS секреты можно перегенерировать (`secrets:rotate`), клиентские конфиги выдать заново.

## Пересмотреть
Если sops окажется барьером для форков — режим `plain` (открытые файлы в `.gitignore`, FileVault).
