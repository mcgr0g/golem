# 0006 — Один домен, секретные пути, без basic auth

Статус: принято (выбор пользователя для /app).

## Контекст
Basic auth плохо сочетается с WS-клиентами (host omp не документирует передачу credentials), а ссылка collab с ключом и так даёт доступ. Нужен один порт/домен/сертификат.

## Решение
Один виртуальный хост Caddy. Маршрутизация по случайным путям (`app_path`, `ws_path`, `llm_path`), WS-маршруты отвечают только на запросы с `Upgrade: websocket`, остальное — лендинг. Аутентификация там, где она есть: UUID VLESS, Bearer-ключ cliproxyapi, ключ комнаты omp. Сверху: Caddy rate limit, fail2ban по access-логу, UFW.

## Последствия
- Секретные пути = секреты (sops), в логах/доках не светить.
- `/r/*` — путь фиксирован протоколом, не секретен; защита ключом комнаты и rate limit.
- Лендинг — статическая заглушка, одинаковая для неизвестных путей.

## Пересмотреть
Если появятся клиенты, которым нужен только браузер без знания пути — добавить basic auth на `/<app_path>/` (статику) отдельно.
